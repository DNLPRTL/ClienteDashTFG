## State / action / reward

### State

Not a controller state. CausalSim models observed variables, actions/interventions and latent factors that influence trace evolution.

### Action

Not a bitrate policy action in the TFG sense. In the causal formulation, actions/interventions can be the decisions of an ABR algorithm whose counterfactual effect on traces must be modeled.

### Reward / QoE

Not a reward-learning source. It evaluates simulation accuracy for outcomes such as stall rate, perceptual quality and buffer occupancy.

## Relevance to DashClientModular4

### What this source justifies

- Trace-driven simulation is only valid under assumptions; the exogenous trace assumption can fail for ABR.
- Throughput observed during chunk downloads can be influenced by the bitrate/chunk selected by the ABR algorithm.
- Dry-runs/logs generated by DashClientModular4 controllers cannot automatically become training traces.
- Evaluation claims must distinguish exogenous network traces from controller-contaminated logs.

### What this source does NOT justify

- It does not require implementing CausalSim.
- It does not make trace-driven evaluation impossible; it makes assumptions explicit.
- It does not authorize training on biased local dry-runs.

### Risks for this TFG

- Leakage risk: BLOCK if training uses legacy dry-runs or controller-generated logs as if they were exogenous capacity traces.
- Future-information risk: medium; causal/counterfactual labels must not leak into model inputs.
- Reward hacking risk: indirect.
- Overfitting risk: high if traces are narrow and biased.
- Hardware risk: high for implementing CausalSim; low for using it as a gate.
- Dependency risk: medium/high if attempting full reproduction.

## Decision impact
