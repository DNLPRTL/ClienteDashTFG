# Why not full offline RL as base

Status: **full offline RL rejected as Phase 4 base**

## Decision

Do not select full offline RL as the primary implementation path.

## Reasons

Offline RL can be attractive because it learns from logged data without online exploration.
However, it requires a trustworthy logged dataset and a clear behavior policy.
This project does not currently have such a dataset.

Dry-runs legacy are explicitly not valid training data because logs generated by a controller can reflect that controller's decisions and therefore bias trace replay.
Without a correct logged-policy/data contract, offline RL can learn out-of-distribution or invalid actions.

## What is retained

Offline RL literature remains useful for:

- understanding logged-data risk;
- discussing OOD actions;
- explaining why we prefer supervised imitation from controlled expert labels;
- future work if a valid logged dataset becomes available.

## Implementation consequence

The selected method uses behavior cloning from generated expert labels on controlled train traces, not unconstrained offline RL from legacy logs.
