# Phase 6B Evaluation Readiness Report

Status: Phase 6B report contract, still active as a readiness preflight after Phase 6C materialization. No benchmark has been run.

The Phase 6B readiness report is generated by:

```powershell
python scripts\check_phase6_evaluation_readiness.py --output <path>
```

Optional manifest-backed mode:

```powershell
python scripts\check_phase6_evaluation_readiness.py `
  --phase4-dataset-manifest <phase4_manifest.json> `
  --phase6-candidate-manifest <phase6_candidate_manifest.json> `
  --output <path> `
  --strict
```

## Output Schema

```json
{
  "schema_version": "phase6_evaluation_readiness_v1",
  "strict": true,
  "ready_for_phase6c": true,
  "ready_for_benchmark": false,
  "benchmark_authorized": false,
  "checks": [],
  "errors": [],
  "warnings": [],
  "notes": [],
  "manifest_audit": {}
}
```

## Semantics

`ready_for_phase6c` means the repo-side readiness gates are structurally satisfied. It authorizes the next dataset materialization and manifest work outside the repository.

`ready_for_benchmark` is always `false` in Phase 6B.

`benchmark_authorized` is always `false` in Phase 6B.

These fields intentionally prevent a readiness report from being misread as benchmark approval.

## Manifest Audit Summary

When manifests are provided, `manifest_audit` summarizes:

- whether manifest validation ran;
- strict validation validity and error count;
- whether the Phase 4 overlap audit allows the Phase 6 candidate for evaluation;
- audit blocking reasons;
- audit counts including checksum and canonical content fingerprint coverage.

When manifests are not provided, `manifest_audit.ran=false` and `warnings` includes:

```text
manifest_audit_not_run
```

This warning is expected before Phase 6C materializes real candidate manifests outside Git. After Phase 6C, the preflight can be run with the external Phase 4 reference and Phase 6 candidate/final manifest paths, but it still does not authorize a benchmark.

## Non-Result Boundary

The readiness report is not:

- a benchmark result;
- a result table;
- a plot source;
- a controller ranking;
- a winner declaration;
- a QoE improvement claim.

No final Phase 6 trace IDs are frozen until `phase6_trace_manifest_final.json` exists after Phase 6C materialization and eligibility audit.

Even after that external freeze, `ready_for_benchmark=false` and `benchmark_authorized=false` remain mandatory until a later benchmark phase explicitly opens execution.
