# Phase 5.5 futura - Verificacion defendible del cliente y baselines

Esta nota recoge una idea para despues de Phase 5 y antes de la evaluacion
formal: una fase de verificacion humana del cliente y de los controllers
clasicos.

Objetivo propuesto:

```text
demostrar que el cliente, la telemetria y los controllers clasicos funcionan de
forma coherente antes de usarlos como base de comparacion en Phase 6
```

Contenido esperado:

- ejecuciones controladas con varios controllers no IA;
- documentos de evidencia de streaming cliente-servidor;
- trazabilidad de decisiones ABR por segmento;
- explicacion de por que BBA, BOLA, MPC y RobustMPC se comportan de forma
  coherente con sus specs locales;
- sin ranking final ni claims de mejora.

Esta fase no se implementa dentro de Phase 5. Queda como preparacion conceptual
para que Phase 6 no compare sobre un cliente opaco.
